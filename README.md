# Wine Cultivar Classifier — ML with scikit-learn + pandas

A structured-data classification project: predict a wine's cultivar
from 13 chemical measurements. Built to practise the exact loop ML
intern roles ask for — data inspection, preprocessing, model
comparison, and honest evaluation on held-out data.

## Dataset

scikit-learn's bundled Wine dataset: 178 samples, 13 features,
3 cultivars (59 / 71 / 48 samples per class), zero missing values.
It ships with scikit-learn, so the project runs offline with no
downloads and no synthetic data.

## Pipeline

```
load_wine()
      │  inspect: shape, class balance, missing values
      ▼
stratified train/test split (75/25, random_state=42)
      │  stratification keeps the class ratio identical in both sets
      ▼
StandardScaler — fitted on TRAINING data only
      │  (fitting on all data would leak test information into the scaler)
      ▼
train 3 models: logistic regression, random forest, SVM
      ▼
evaluate on the held-out test set (45 samples)
```

Honest context: this is a small, famously well-separated dataset, so
perfect scores here mean the pipeline is correct — not that the model
would survive messy real-world data. The value of this project is the
pipeline discipline (no leakage, stratified split, model comparison),
not the headline number.

## Usage

```bash
pip install -r requirements.txt

# Train, compare models, save the best one to models/
python main.py

# Predict one sample (13 values, in dataset order — see predict.py)
python predict.py 14.23 1.71 2.43 15.6 127 2.8 3.06 0.28 2.29 5.64 1.04 3.92 1065
```

## What I practised

- **Preprocessing**: train/test split discipline, scaling without leakage
- **Model comparison** instead of tuning a single model in the dark
- **Evaluation beyond accuracy**: per-class precision/recall, confusion matrix
- **Reproducibility**: fixed random state, saved model + scaler for inference

## Limitations

- Tiny, clean, classic dataset — no missing values, no outliers, no
  class imbalance to handle. A production version would need all three.
- The saved model file (`models/`) is generated by running `main.py`
  and is intentionally not committed.
- Next steps that would genuinely extend this: cross-validation
  instead of a single split, hyperparameter search, and a messier
  real-world dataset.
